# PROCESS LAB · API v1 (контракт для Миланы, Камилы и Кристины)

**Host:** `http://127.0.0.1:8765` • **Content-Type:** `application/json` • **Доступ:** только локально • **Версия JSON-модели:** `version: 3`.

## Endpoints

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/v1/health` | Проверка доступности сервера |
| GET | `/api/v1/demo` | Демо-модель v3 (НЕ фактические замеры) |
| POST | `/api/v1/validate` | Проверить модель, не запускать симуляцию |
| POST | `/api/v1/simulate` | Запуск модели и расчёт KPI |
| POST | `/api/v1/compare` | Расчёт пары сценариев и разницы показателей |
| GET | `/` | Страница фронтенда (сервер раздаёт только разрешённые статические файлы) |

## Запрос симуляции

```json
{
  "model": {
    "version": 3,
    "name": "Фабрика процессов",
    "nodes": [{"id": "wh", "type": "warehouse", "name": "Склад", "x": 0, "y": 0}],
    "edges": [],
    "settings": {"target": 10}
  }
}
```

**Это только иллюстрация структуры:** такой неполный пример вернёт `422`. Полный валидный запрос — объект из `data/factory_demo_v3.json`, который совпадает с экспортом кнопки **«Экспорт»** на сайте (при экспорте модель может быть вложена в ключ `model`).

```javascript
const result = await fetch('/api/v1/simulate', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({model: state.model})
}).then(response => response.json());
```

## Ключевые поля запроса

### `nodes[]` — сущности потока

- `id`, `type` (`warehouse`, `operation`, `qc`, `customer`), `name`, `x`, `y` — данные карты.
- Для `operation` и `qc`: `cycle` (секунды), `staff` (человек), `variation` (%), `defect` (%), `availability` (%), `setup` (секунды).

### `edges[]` — материальные связи

- `{ "from": "o3", "to": "o4" }`. Каждая операция должна вести к ОТК. При входе нескольких ребер требуется одна подсборка с **каждого**.
- `kpsc.infoLinks[]` — информационные стрелки, НЕ входят в `edges` и не участвуют в расчёте.

### `settings` — основные настройки

- `target`: план годных изделий; `releaseUnits`: количество стартовых комплектов.
- `shiftMinutes`: длительность раунда, `taktSeconds`: такт заказа.
- `productionBatch`, `transportBatch`, `initialStock`, `initialFlowWip`, `partialTransport`.
- `logistCount`, `handlingSeconds`, `speed`, `returnMultiplier`, `layoutLogistics`.
- `seed`: воспроизводимость вариаций и брака.
- `materialCost`, `salePrice`, `wageHour`, `logistWageHour`, `equipmentShift`, `rentShift`, `overheadShift`.
- `metersPerPixel` содержится в формате старого JS-контракта, но в v2 физические расстояния берутся из `kpsc.floor`.

### `kpsc.floor`

- Словарь `{ "o1": [11.5, 4.6], ...}` в метрах. Координаты расположения **физических** рабочих мест, в отличие от визуальных `nodes[].x/y`.

### `kpsc.meta`, `kpsc.issues`, `kpsc.extras`

- Документируемые параметры / отметки проблем / символы карты; НЕ являются скрытыми затратами и НЕ участвуют напрямую в обработке событий.

## Ответ `POST /api/v1/simulate`

Сохраняет имена из `frontend/app.js`:

| Путь | Содержание |
|---|---|
| `accepted` | Количество принятых заказчиком за раунд |
| `target` | План выпуска |
| `finished` | Годные после ОТК (может быть больше accepted) |
| `avgFlowSec` | Среднее время прохождения продукции для принятых изделий; `null`, если нет выпуска |
| `wip`, `stageQueue`, `waitingTransport` | НЗП и ожидание, в т. ч. подсборок |
| `throughputPerHour` | Производительность по принятым изделиям |
| `perOp[]` | Статистика операций: `started`, `processed`, `good`, `scrap`, `utilization`, `avgWaiting`, `maxQueue` |
| `logistics` | `trips`, `distance` (м), `utilization`, `waiting` |
| `financial` | `laborCost`, `materialCost`, `totalCost`, `profit`, `revenue`, `costPerUnit` |
| `bottleneck` | Сильнее всего загруженная операция по простой эвристике, не формальное доказательство причины ограничения |
| `series[]` | Сданные изделия по шагам времени такта |
| `issues[]` | Диагностические сообщения о демо-расчёте |
| `methodology` | **Дополнительный блок** оценки критического пути, времени создания ценности, теоретического темпа и оговорок о данных |

**Важный терминологический момент:** `methodology.theoreticalCriticalPathSec` не равен реальному ВПП: не учитывает ожидания, очереди и брак. `bottleneck` использует эвристику по загрузке, а не полноценный анализ ограничений производства.

## Запрос сравнения

```json
{ "baseline": {"...": "полная модель"}, "candidate": {"...": "полная изменённая модель"} }
```

Ответ: `baseline`, `candidate` — расчётные результаты; `delta.accepted`, `delta.wip`, `delta.profit`, `delta.avgFlowSec` и др. содержат `before`, `after`, `change`. `analysis` — методические показатели для обеих моделей.

## Ошибки

- `422` — некорректная модель (`{"error":"invalid_model","message":"..."}`), например цикл на КПСЦ, отрицательное время или нарушение структуры входов.
- `404` — несуществующий маршрут.
- `500` — внутренняя ошибка сервера (полный стек не отправляется пользователю).

## Что проверить при интеграции

1. Базовый сценарий: `accepted = 9`, `logistics.trips = 68`, `wip = 24` **в исходных демо-данных**.
2. При перетаскивании карточки на КПСЦ (`nodes[].x/y`) расчёты не меняются.
3. При перемещении физического рабочего места (`kpsc.floor`) транспортные расстояния меняются.
4. Если опубликовать `kpsc.infoLinks`, они не должны создавать материальные зависимости.
5. Если добавить цикл, сервер возвращает `422`, а не ложные финансовые итоги.

## Ограничения и безопасность

Демонстрационный HTTP-сервер **не имеет учётных записей, TLS и серверного хранилища**. `backend.server` позволяет прослушивать только loopback-адрес. Не использовать для персональных данных и не развёртывать публично до добавления защищённой авторизации и работы с ФЗ-152.
